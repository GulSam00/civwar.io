# IO 게임 디자인 — 실시간 영토 정복 장르

territorial.io, generals.io, diep.io 같은 "브라우저에서 바로 붙는" 실시간 멀티플레이어 게임은 공통적으로 **단순한 규칙 + 빠른 세션 + 서버 결정론적 시뮬레이션**이라는 구조를 가진다. 규칙이 복잡할수록 신규 플레이어 이탈률이 높아지고, 서버가 비결정론적일수록 멀티플레이어 동기화가 깨진다.

## GDD 필수 섹션과 작성 순서

아래 순서로 작성한다. 뒤 섹션은 앞 섹션의 수치에 의존하므로 순서를 지킨다.

### 1. 핵심 루프 (Core Loop)
한 플레이어가 게임 내내 반복하는 행동 사이클을 한 문장으로 정의한다. 예: "영토를 점령한다 → 병력이 자동 생산된다 → 인접 영토를 공격한다 → 반복". 핵심 루프가 두 문장 이상으로 설명되면 규칙이 과하게 복잡한 것이다 — 줄인다.

### 2. 맵 / 영토 시스템
- 맵의 최소 단위(타일, 폴리곤 지역 등)와 인접 규칙(4방향/6방향/그래프 인접)
- 맵 크기와 플레이어 수의 관계 — 맵이 클수록 초반 확장 시간이 늘어 세션이 길어진다
- 중립 영토(미점령) 처리 여부

### 3. 자원·성장 모델
- 영토가 시간에 따라 무엇을 생산하는지(병력/자원)와 생산 공식 (예: `초당 생산량 = 기본값 × 보유 영토 수^감쇠계수`)
- 감쇠계수를 넣는 이유: 선형 성장이면 초반에 앞선 플레이어가 눈덩이처럼 격차를 벌려 후반 긴장감이 사라진다. 완전 동등한 감쇠는 역전 기회를 만들지만 과하면 확장 동기가 사라진다 — 초안 값을 제시하고 "실전 테스트로 조정 필요"라고 명시해도 된다.
- 반드시 **서버 tick 단위로 계산 가능한 이산 공식**으로 적는다. 연속 함수는 서버 구현 시 다시 이산화해야 하므로 처음부터 tick 기준으로 쓴다.

### 4. 전투 해석 규칙
- 공격 시 병력을 어떻게 비교하는지, 점령 조건은 무엇인지
- 방어 보너스, 지형 보너스 등 변수 유무 (없어도 된다 — 없는 것이 세션을 단순하고 예측 가능하게 만든다)
- 동시 다발 공격(여러 플레이어가 같은 타일을 동시에 공격) 처리 규칙 — tick 기반 서버에서는 반드시 명시해야 한다. 안 정하면 백엔드가 임의로 정하게 되고, 그 결정이 GDD와 어긋난다.

### 5. 세션 페이싱 (목표: 30~60분)
다음 공식으로 **평균 세션 길이를 추정**하고 GDD에 계산 과정을 남긴다:

```
예상 세션 길이 ≈ 초기 확장 단계 + 중반 교전 단계 + 종반 정리 단계

초기 확장 단계 ≈ (맵 타일 수 / 플레이어 수) / 확장 속도(타일/분)
중반 교전 단계 ≈ f(플레이어 수, 평균 승부 결정 속도)
종반 정리 단계 ≈ 남은 영토 수 / 마무리 공격 속도
```

정확한 시뮬레이션이 불가능하므로 대략적 추정이어도 된다. 핵심은 **"왜 이 수치면 30~60분에 수렴하는지"의 근거를 남기는 것** — 근거 없이 숫자만 있으면 다음 반복에서 조정할 기준이 없다.

레버(조정 가능한 변수) 우선순위:
1. 맵 크기 / 플레이어 수 비율 — 세션 길이에 가장 직접적인 영향
2. 성장률 — 너무 빠르면 초반에 승부가 나서 세션이 짧아지고 뒷심 플레이어가 재미를 못 느낌
3. 승리조건 임계값 (아래 참조)

### 6. 승리조건
IO 장르에서 흔히 쓰는 세 가지 중 게임 정체성에 맞는 것을 고른다:
- **최후 생존**: 마지막까지 살아남은 플레이어 승리 (generals.io 계열 — 영토 0이 되면 탈락)
- **영토 점유율**: 일정 비율(예: 60%) 이상 점유 시 즉시 승리, 또는 제한시간 종료 시 최다 점유
- **수도/거점 점령**: 특정 타일(수도)을 뺏기면 탈락 또는 게임 종료

제한시간을 반드시 둔다 (세션 페이싱 목표를 강제하는 안전장치). 제한시간 도달 시 승리조건이 안 정해졌으면 어떻게 판정하는지도 명시한다.

### 7. 클라이언트-서버 이벤트 초안
백엔드가 프로토콜을 설계할 1차 입력이다. "무엇이 발생하고 무엇을 동기화해야 하는가"를 나열한다 — 정확한 메시지 포맷은 백엔드의 몫이니 이 단계에서는 이벤트 이름과 의미만 정한다.

예시:
```
- 플레이어 입장/퇴장
- 공격 명령 (출발 영토, 도착 영토, 투입 병력 비율)
- 게임 상태 갱신 (매 tick, 모든 영토 소유자/병력 수)
- 게임 종료 (승자, 종료 사유)
```

## 출력 템플릿

```markdown
# civwar.io 게임 디자인 문서

## 1. 핵심 루프
## 2. 맵 / 영토 시스템
## 3. 자원·성장 모델
## 4. 전투 해석 규칙
## 5. 세션 페이싱
### 계산 근거
## 6. 승리조건
## 7. 클라이언트-서버 이벤트 초안
## 미결정 사항 (Open Questions)
```

"미결정 사항"은 비워두지 않는다 — 트레이드오프가 있어 확신이 없는 항목을 여기 남기면, 나중에 실전 플레이 피드백으로 채울 수 있다.
