# 이슈 관리 (docs/issues)

여러 머신에서 git 으로 이어받는 이슈 트래커다. 외부 트래커(Notion, GitHub Issues)는 쓰지 않고 모든 상태는 `docs/issues/*.md` 파일이다. 포맷 상세와 예시는 `docs/issues/README.md`.

## 파일 규칙
- 이슈 하나 = 파일 하나: `docs/issues/<id>.md`. id 는 `YYYYMMDD-HHmm-<kebab-slug>` (로컬 시각). 순번(001)은 쓰지 않는다 — 머신 간 충돌.
- frontmatter: `id`(파일명과 같아야 함), `title`, `status`(todo|doing|later|done), `priority`(high|medium|low), `created`(YYYY-MM-DD), `external`(비워 둠).
- 본문 섹션: `## 맥락` / `## 완료 조건`(체크리스트) / `## 로그`(`- YYYY-MM-DD: 한 줄`).
- **파일은 삭제하지 않는다.** 완료는 `status: done`.

## 언제 무엇을 하나
- **추가**: 새 파일을 만든다. 다른 머신의 사람이 읽어도 이해되게 맥락에 근거(파일 경로, 측정 수치, 결정 이유)를 적는다.
- **조회**: 세션 시작 훅 출력 또는 `node .claude/skills/issues/list-issues.mjs`. 세부는 해당 파일을 읽는다.
- **진행/완료**: `status` 를 바꾸고(`doing` → `done`), 체크리스트를 체크하고, 로그에 날짜와 한 줄을 추가한다. 중단하는 경우엔 어디까지 했고 다음이 무엇인지 로그에 남겨 다른 머신이 이어받게 한다.
- **범위 밖 문제를 발견했을 때**: 고치지 말고 `status: later` 로 기록한 뒤 사용자에게 한 줄로 알린다 ("범위 밖 문제를 이슈로 남김: <id>"). 지금 작업과 무관한 수정을 끼워 넣지 않는다.
- 사용자가 설계 결정을 해야 하는 일은 맥락에 "결정 필요: …"를 적는다.

## 커밋·push
- 이슈 파일 변경은 **관련 코드 변경과 같은 커밋**에 넣는다. 이슈만 바뀌었으면 `chore(issues): …` 로 따로 커밋한다.
- 이 프로젝트의 커밋 끝에는 시스템 안내의 `Co-Authored-By` 줄을 붙인다.
- **push 하지 않는다.** 세션을 마무리할 때 사용자에게 push 할지 묻는다.

## 금지
- 비밀값(.env 값, 토큰, 키, 비밀번호)을 이슈 파일에 기록하지 않는다. 필요하면 "어디에 있는지"만 적는다.
- 이슈 파일 삭제, id 변경(파일명 변경 포함) 금지.
