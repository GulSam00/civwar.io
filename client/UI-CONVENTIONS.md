# civwar.io 클라이언트 UI 규칙

게임 화면 UI와 디자인을 만들거나 고칠 때 따르는 규칙이다. 흩어져 있던 사용자 결정(`_workspace/00_input/design-decisions.md`), 구현 기록(`_workspace/03_frontend_integration-notes.md`), 코드 관례를 한곳에 모았다.

- 규칙이 서로 부딪히면 **날짜가 늦은 사용자 결정**이 이긴다. 새 결정이 생기면 design-decisions.md에 먼저 적고, 이 문서를 고친다.
- 각 항목 끝의 괄호는 근거다. 날짜만 있으면 design-decisions.md의 그날 항목이다.

## 1. 톤과 대상

- **깔끔한 플랫**이다. 단색 타일에 또렷한 플레이어 색을 쓰는 territorial.io 계열이다. 그라데이션 장식, 그림자 남발, 둥근 카드 겹치기는 쓰지 않는다. (2026-10-09)
- **PC 우선**이다. 마우스와 단축키가 기본이고, 모바일은 관전과 간단한 조작만 지원한다. (2026-10-09)
- CSS 프레임워크는 쓰지 않는다. 스타일은 `client/src/styles.css` 한 파일에 둔다.

## 2. 정보 표시 원칙

- **화면 본문에는 수치와 아이콘만 둔다.** 맵, HUD, 패널 본문에 설명 문장을 넣지 않는다. (2026-10-24 "수치만 보여 주고 설명 문구는 뺀다")
- **설명은 hover 툴팁, `?` 도움말, 도움말 페이지(`ui/Help.tsx`)에만 둔다.** 처음 보는 요소(부대 선택 패널 항목, 수비 깃발의 파란 점선, 출전 버튼 능력치 등)는 이 경로로 설명한다. (2026-10-29 사용자 결정. 10-24 원칙과 10-28 UI 요청을 합친 것)
- **신규 유저 안내는 남긴다.** 튜토리얼은 없고 도움말만 둔다. (2026-10-09, 2026-10-24)
- **수치는 절대값으로 쓴다.** `0.85`, `×1.15` 같은 배율이나 소수를 그대로 보여 주지 않는다. "칸당 6명", "+120 골드/분", "함락까지 약 300명"처럼 바로 계산할 수 있는 값으로 바꿔 쓴다. (2026-10-28 사용자 요청)
- 큰 수는 `ui/fmt.ts`의 `fmtCompact`로 줄인다(`2.55K`, `1.23M`). 유효숫자 3자리이고 반올림이 아니라 버림이다.
- 표시 계산은 서버 규칙과 같은 식을 써야 한다. 상수와 수식은 `@civwar/shared`(`constants.ts`, `combatMath.ts`, `dispatch.ts`)에서 가져오고, 클라이언트에 숫자를 따로 적지 않는다.
- 결과를 보여 준다. 커서와 미리보기는 "이 명령이 무엇을 일으키는지"(진격 경로, 점령 비용, 예상 교전)를 보여 준다. (A-5, 2026-10-10)
  - A-5 초기판은 공격·방어 태세를 UI에 드러내지 않는다고 했다. 그 뒤 교전 시각화(2026-10-11, 검·방패 아이콘)와 태세 명령이 생겨서 지금은 태세를 화면에 표시한다.

## 3. 색

- 토큰은 `styles.css`의 `:root`에 있다. 새 색이 필요하면 hex를 직접 쓰지 말고 토큰을 먼저 쓰거나 새로 만든다.

  | 토큰 | 값 | 쓰임 |
  |---|---|---|
  | `--bg` / `--panel` / `--panel-2` | `#121a24` / `#1c2733` / `#243240` | 배경, 패널, 패널 안쪽 |
  | `--line` | `#33465a` | 테두리, 구분선 |
  | `--text` / `--muted` | `#e8edf2` / `#94a3b3` | 본문, 보조 글자 |
  | `--primary` / `--primary-hi` | `#2f80ed` / `#4a93f5` | 주 버튼, 강조 |
  | `--atk` / `--def` | `#ff3b30` / `#2f80ed` | 공격 태세(빨강), 방어 태세(파랑) |
  | `--warn` / `--danger` | `#ffb300` / `#e53935` | 경고, 위험 |
  | `--radius` | `6px` | 모서리 |

  - 지금 `styles.css`에는 토큰을 쓴 곳이 240곳, hex를 직접 쓴 곳이 104곳이다. 고칠 일이 생긴 곳부터 토큰으로 바꾼다.
- 맵 색은 캔버스용이라 `render/palette.ts`에 따로 있다.
  - **지형 7종**(`TERRAIN_RGB`)은 채도 낮은 단색이다.
  - **플레이어 12색**(`PLAYER_HEX`)은 채도가 높고 서로, 그리고 지형과 구분된다.
  - 소유 칸은 플레이어 색을 42%(`OWNER_FILL_ALPHA`) 반투명으로 겹쳐서 지형이 비치게 한다. 소유 경계는 경계선과 영토 안쪽 띠가 맡는다. (2026-10-10)
  - 기지 체력 바는 공격자 색으로 차오른다. 플레이어 팔레트를 그대로 쓴다. (비주얼 기획 제약 3)
- **색만으로 구분하지 않는다.** 플레이어마다 다른 무늬(`render/patterns.ts`)를 색각 보조 옵션으로 겹친다. 새 상태 표시도 색과 함께 모양·아이콘·선 종류(실선/점선) 중 하나를 같이 바꾼다. (비주얼 기획 제약 4)

## 4. 아이콘

- 아이콘은 **24 격자 inline SVG 선 아이콘**이다. `stroke="currentColor"`, `strokeWidth={2}`, 둥근 끝을 쓴다. 이모지를 아이콘 대신 쓰지 않는다(이모지는 플레이어 이모트 기능에만 쓴다).
  - HUD: `ui/hudIcons.tsx`
  - 병종: `ui/unitIcons.tsx`. 모양 데이터는 `render/unitGlyphs.ts`와 공유해서 캔버스 깃발 마커와 같은 그림이다.
  - 테크: `ui/techIcons.tsx`
- 병종은 글자 대신 아이콘으로 표기한다. 공간이 넉넉한 곳(도움말, 깃발 패널)만 이름을 옆에 붙인다(`withName`). (2026-10-11)
- 장식용 아이콘은 `aria-hidden="true"`, 뜻이 있는 아이콘은 `role="img"`와 한국어 `aria-label`을 단다.

## 5. 문구

- UI 문구는 한국어로 쓴다(CLAUDE.md 언어 규칙).
- 재사용하는 이름과 메시지는 `ui/text.ts`에 둔다. 병종, 태세, 지형, 깃발 상태 이름과 서버 거절 사유(`REJECT_TEXT`), 오류(`ERROR_TEXT`)가 여기 있다.
  - `REJECT_TEXT`는 `Record<CmdRejectReason, string>`이다. 서버에 거절 사유가 생기면 여기에 문구를 넣지 않는 한 타입 검사가 실패한다. 서버 변경과 같이 고친다.
- 서양식 지명은 한국어 음차로 쓴다. (2026-10-18)
- 버튼과 라벨은 짧은 명사나 동사로 쓴다. 문장은 툴팁과 도움말에만 쓴다(2절).

## 6. 화면 구성과 조작

- 화면 전환은 서버의 명시적 메시지로만 한다. 클라이언트가 추측해서 화면을 바꾸지 않는다. (`react-game-client` 스킬)
- 정해진 조작(바꿀 때는 사용자 결정이 필요하다)
  - 맵 지점 클릭 → 가장 가까운 기지 자동 강조, 기지에서 그 지점까지 점선 화살표로 진격 경로, 클릭 지점에 창·검·기병 선택지가 삼각형으로 뜬다. (2026-10-10)
  - 우클릭 = 이동. 부대를 선택하지 않았을 때만 우클릭 원형 메뉴가 뜬다. (2026-10-14, 2026-10-18)
  - 깃발 선택 후 기지 클릭 = 그 기지로 회수. (2026-10-10)
  - 모든 깃발(적 포함)의 진행 방향을 보여 준다. 옵션에서 전부/내 것만/끄기를 고른다. (2026-10-09, `ui/options.ts`)
- 팝업(테크, 외교 등)은 드래그할 수 있고 위치를 기억한다(`ui/draggable.ts`). (2026-10-14)
- 지형 hover 툴팁은 세로로 쌓는다. 표시할 항목은 옵션 창에서 고른다(`TOOLTIP_FIELDS`). 부대를 선택한 동안에는 그 부대의 행동에 필요한 항목만 보여 준다. (2026-10-11, 2026-10-28)
- 표시 설정(색각 보조, 이동 방향, hover 항목)은 옵션 창 한곳에 모은다. 설정은 `localStorage`의 `civwar.options.v1`에 저장하고, 읽을 때 `sanitizeOptions`로 검증한다. (2026-10-11)

## 7. 코드 구조

- **서버가 권위다.** 서버 값이 오면 항상 덮어쓴다. 프로토콜 필드명은 `_workspace/02_backend_protocol.md` 그대로 쓰고, 타입은 `@civwar/shared`에서 가져온다. 클라이언트에서 다시 정의하지 않는다.
- 렌더 루프(`requestAnimationFrame`)와 상태 갱신을 분리한다. 루프는 마운트할 때 한 번만 시작하고, 최신 상태는 ref로 읽는다. 캔버스 그리기는 `render/`에 둔다.
- **표시 계산은 React 컴포넌트 밖의 순수 함수로 둔다.** 예: `ui/terrainInfo.ts`, `ui/unitStats.ts`, `ui/morale.ts`, `ui/techTree.ts`. 이 함수에는 `client/test/`에 단위 테스트를 붙인다. 컴포넌트(`GameScreen.tsx`, `TechWindow.tsx` 등)는 그 결과를 그리기만 한다.
- 파일 줄바꿈은 LF다. Windows에서 저장하다 CRLF로 바뀌지 않게 주의한다(feabdc1에서 실제로 한 번 일어남).

## 8. 바꾼 뒤 확인

1. `npm run typecheck`와 클라이언트 테스트(`npx vitest run --root client`)를 통과시킨다. vite 빌드는 타입 검사를 하지 않으니 빌드 통과만으로 끝내지 않는다.
2. 미리보기(dev 서버)에서 바꾼 화면을 실제로 hover·클릭해 보고 스크린샷으로 남긴다(`_workspace/ui-<날짜>/`).
3. 구현 결정을 `_workspace/03_frontend_integration-notes.md`에 회차로 덧붙인다. 사용자가 정한 것이면 design-decisions.md에도 적고 이 문서를 고친다.
