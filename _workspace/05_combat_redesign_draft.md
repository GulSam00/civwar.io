## 2. 수식

모든 계산은 서버 tick 4a(읽기)·4b(갱신)에서 정수/‰로 결정론적이며 단계마다 floor 한다.

### 2.1 채널과 기본값

```
CHANNELS = [ATK, DEF]               // 채널 추가 시 뒤에 붙인다
UNIT_STAT[c][unit]                  // 병종 기본 능력치 (3.절)
TERRAIN_BUFF[terrain][posture][c]   // ‰ (4.절)
BASE_BUFF[posture][c]               // 자기 기지 칸 ‰ = 전부 1300
POSTURE_W[posture][c]               // 공격 태세 [600,400], 방어 태세 [400,600]
```

### 2.2 깃발의 채널값 `a_c(f)`

```
B_c(f) = onOwnBase(f) ? BASE_BUFF[posture_f][c] : TERRAIN_BUFF[terrain(pos_f)][posture_f][c]
x      = floor(UNIT_STAT[c][unit_f] * B_c(f) / 1000)
x      = floor(x * techChannelPm(stat_owner, unit_f, c) / 1000)
x      = floor(x * moraleMult(unit_f, m_f, stat_owner) / 1000)      // 5.절
if (disengage) x = floor(x * 700 / 1000)
a_c(f) = max(1, x)
```

깃발이 서 있는 **자기 칸**의 지형만 읽는다. 기지 칸은 지형 항을 대체한다(곱하지 않음).

### 2.3 편의 채널값과 가중치

```
V_c(s)   = max(VMIN=100, floor( Σ troops_f * a_c(f) / Σ troops_f ))
ωA(s)    = floor( Σ troops_f * POSTURE_W[posture_f][ATK] / Σ troops_f )
ω_ATK(s) = ωA(s),  ω_DEF(s) = 1000 - ωA(s)
```

### 2.4 채널별 비교 (γ=2)

```
inv_c(s) = floor( 10^12 / V_c(s)^2 )
λ_c(s)   = floor( 10^6 * inv_c(s) / Σ_t inv_c(t) )
```

### 2.5 합성 → 손실 배분

```
raw(s)  = ω_ATK(s) * λ_ATK(s) + ω_DEF(s) * λ_DEF(s)             // <= 10^9
loss(s) = floor( T * raw(s) / Σ_t raw(t) )                      // T = 편 수 * L (불변)
잔여 = T - Σ loss(s) 를 편 key ASC 로 순환하며 1 milli씩 가산 (현행 방식)
loss(s) = min(loss(s), 편 병력)
```

정수 범위: `T * raw`는 T ≤ 약 9×10^6 milli까지 2^53 미만(현행 `T*iv`와 같은 수준). 사기 곱 상한 1500‰이므로 V는 수천 이하, `inv_c`는 하한이 충분히 크다.

- 기지 방어(양 채널 ×1.3)는 구릉(1.3, DEF만)보다 강하고 산(1.6)보다 약하다.

**약소국 정리 병목(방어 돌파력)에 미치는 영향**: 기지를 지키는 방어자(평지 출발 공격자 기준)를 깨는 데 필요한 최소 공격 병력(사기 없음 / 사기 있음, 동시 교전 시작·끝까지):

| 공격자 → 방어자 | 현행 | 신규 ×1.5 한 채널 | 신규 ×1.3 한 채널 | **신규 ×1.3 양 채널** |
|---|---|---|---|---|
| 창병 → 기지 검병 200 | 350 | 270 / 210 | 240 / 180 | **300 / 230** |
| 검병 → 기지 검병 200 | 310 | 310 / 310 | 270 / 270 | **350 / 340** |
| 기병 → 기지 검병 200 | 260 | 350 / 420 | 310 / 380 | **410 / 510** |
| 검병 → 기지 창병 300 | 590 | 500 / 650 | 440 / 580 | **580 / 770** |
| 기병 → 기지 창병 300 | 500 | 530 / 780 | 490 / 730 | **640 / 1010** |

- 사기가 없을 때(왼쪽 수)는 검병 기준 현행과 비슷하다(310 → 350, 590 → 580). 즉 기지 돌파 난이도 자체는 **현행 ×1.5와 큰 차이 없다**(±15%).
- **사기가 있으면 기지 돌파가 어려워진다**: 공격자는 교전 동안 사기가 줄고 방어자도 같이 줄지만, 필요 병력이 검병 기준 +0~30%(580 → 770), 기병 기준 +25~60%(500 → 1010 vs 창병 방어). 기병이 약소국 정리의 주력이면 병목이 커진다. 반대로 창병이 공격자일 때는 현행보다 쉬워진다(350 → 300).
- 판단: 약소국 정리의 병목이 더 심해질 가능성이 있다 (마지막 기지 공격 도달률 측정 필수, B.1). 조정 레버는 `BASE_BUFF` (예: 1300 → 1200) 와 `MORALE_DROP_PER_TICK` (기병 감소율 하향)이며, 상수 변경만으로 가능하다.

## 5. 사기

> 사용자 정의: 매 전투마다 줄고, 줄면 전투력도 준다. **rev.4 확정**: 깃발 단위, 모든 병종 동일한 곱(만땅 +10% ~ 바닥 −40%), 병종 차이는 감소율(창 3 / 검 6 / 기 10 ‰/tick)만, 회복 R1, 기병 단기 돌파는 테크 노드.

### 5.1 설계 요약

| 항목 | 값 |
|------|-----|
| 단위 | 깃발 `morale` 0~1000‰, 시작 1000 |
| 감소 | 교전(`inCombat`) tick마다 `drop = max(1, floor(DROP[unit] * techDropPm / 1000))`, 기본 창 3 / 검 6 / 기 10 |
| 회복 | 비전투 tick마다 +3‰, 자기 기지 칸 위 +10‰ (× 테크 회복 배율) |
| 곱 | `moraleMult(unit,m) = min(1500, FLOOR + floor((FULL(unit) - FLOOR) * m / 1000))`, FLOOR=600, FULL 기본 1100, `FULL(unit) = 1100 + 테크 기세 가산` |
| 적용 | 두 채널에 곱 (2.2에서 테크 다음, 이탈 앞) |
| 1.0 경계 | m = 800 (사기 곱이 1000이 되는 지점). 그 위는 보너스, 아래는 감쇠 |

### 5.2 병종별 사기 곱 (테크 없음)

| 병종 | 감소 ‰/tick | 사기 0까지 | 곱 ‰: 0 / 5 / 10 / 15 / 20 / 30초 |
|------|------|------|------|
| 창병 | 3 | 약 67초 | 1100 / 1062 / 1025 / 987 / 950 / 875 |
| 검병 | 6 | 약 33초 | 1100 / 1025 / 950 / 875 / 800 / 650 |

기병은 약 4초(m=800까지 20 tick), 검병은 약 7초, 창병은 약 13초 만에 보너스 구간(곱 > 1000)을 잃는다.

### 5.3 갱신 규칙 (결정론)

4b 마지막(inCombat 갱신 이후), 깃발 `flagId ASC`, 모델 2에서만:

```
if (f.inCombat)          m = max(0, m - drop(unit, tech))
else if (onOwnBase(f))   m = min(1000, m + floor(RECOVER_BASE(10) * techRecoverPm / 1000))
else                     m = min(1000, m + floor(RECOVER(3) * techRecoverPm / 1000))
```

정수 ‰ 하나라 순서 의존성이 없고 다음 tick 4a가 읽는다.

### 5.4 기세 테크 요구와 예약 스탯 칸 (노드는 이번 범위 밖)

사용자 요구: **"기병 기세" 업그레이드가 가능해야 한다.** 테크는 사용자가 대폭 수정할 예정이므로 이번에는 스탯 칸만 예약하고 노드는 만들지 않는다. 예약 칸(`TECH_STAT`, 기존 `COMBAT_ATK` + `COMBAT_ATK_<unit>` 패턴과 같은 방식, 공통 1칸 + 병종별 3칸):

## 8. 위험과 대안

### 8.1 위험

1. **기병이 테크 없이는 약하다**: 동수 조우전도 1.5:1 병력 우위에서도 진다(5.5). 기병 테크 개편 전까지 기병 비중이 크게 줄 수 있다 (점령비·속도 이점은 유지). 모델 2는 테크 개편 후 켜는 것이 안전하다.
2. **약소국 정리 병목**: 사기까지 포함하면 기지 돌파 필요 병력이 최대 2배(기병 vs 기지 창병, 2.9). 레버: `BASE_BUFF`, `MORALE_DROP_PER_TICK`.
3. 상성 폭이 사기에 의존: 초반(0~10초)은 폭이 12.8~27.6pp로 약하다.
4. 설명 가능성: 채널 2개 + ω + 지형 + 사기. UI가 부실하면 예측 불가로 느껴짐.
5. 봇 재교정·신규 규칙 비용.
6. 프로토콜: 사기 동기화, `power` 의미 변경.
7. 튜닝 파라미터 증가: ω, γ, VMIN, 지형표, 사기 곱/감소/회복, 기지 배율. 상수만 바꿔 조정할 수 있게 구현한다.
8. 정수 범위는 2.5 분석으로 안전, 테스트 필요.
