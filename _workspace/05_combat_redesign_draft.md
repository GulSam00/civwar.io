## 2. 수식

모든 계산은 서버 tick 4a(읽기)와 4b(상태 갱신)에서 정수/‰로 결정론적이다. 단계마다 floor.

### 2.1 채널과 기본값

```
CHANNELS = [ATK, DEF]               // 인덱스 0, 1. 채널 추가 시 뒤에 붙인다
UNIT_STAT[c][unit]                  // 병종 기본 능력치 (3.절)
TERRAIN_BUFF[terrain][posture][c]   // ‰ (4.절)
BASE_BUFF[posture][c]               // 자기 기지 칸 ‰ (2.2)
POSTURE_W[posture][c]               // 합성 가중 ‰, 태세마다 채널 합 = 1000
```

### 2.2 깃발의 채널값 `a_c(f)`

```
B_c(f) = onOwnBase(f) ? BASE_BUFF[posture_f][c] : TERRAIN_BUFF[terrain(pos_f)][posture_f][c]
x      = floor(UNIT_STAT[c][unit_f] * B_c(f) / 1000)
x      = floor(x * techChannelPm(stat_owner, unit_f, c) / 1000)
x      = floor(x * moraleMult(m_f) / 1000)                       // 5.절. 사기 곱 600~1000
if (disengage) x = floor(x * 700 / 1000)                          // 확정
a_c(f) = max(1, x)
```

- 깃발이 서 있는 **자기 칸**의 지형만 읽는다 (현행과 같음).
- `techChannelPm(stat, unit, ATK) = stat[COMBAT_ATK] + stat[COMBAT_ATK_<unit>]`, DEF는 `COMBAT_DEF` 계열. 기존 `techCombatPm`의 두 분기를 채널 기준으로 나눠 부르면 된다. 테크 데이터는 그대로 [A-D6].
- **기지 행** (값 ×1.3 확정, 채널은 [A-D4]): `BASE_BUFF = { 공격: [ATK 1300, DEF 1000], 방어: [ATK 1000, DEF 1300] }`. 지형 항을 대체한다 (곱하지 않음).

기지 ×1.3 효과 (ω600 γ2, 첫 틱 앞 편 손실%, 병력 표기대로):

| 상황 | 현행(×1.5) | 신규 ×1.5 | **신규 ×1.3 (한 채널)** | 신규 ×1.3 (양 채널) |
|------|------|------|------|------|
| 기병500(공,평지) vs 창병300(방,기지) | 62.3 | 63.3 | **61.4** | 68.0 |
| 검병300(공) vs 검병300(방,기지) | 60.0 | 60.0 | **56.6** | 62.8 |
| 창병300(공) vs 창병300(방,기지) | 69.2 | 60.0 | **56.6** | 62.8 |
| 기지 위 공격 검병300 vs 검병300(방,평지) | 40.0 | 40.0 | **43.4** | 37.2 |
| 기지 위 공격 기병300 vs 창병300(방,평지) | 42.4 | 48.3 | **51.1** | 45.3 |

해석:
- 시나리오 S3(기병500 vs 기지 창병300)을 동적으로 돌리면 현행은 기병이 3명 남기고 이기고, 신규 ×1.3은 기병이 21명 남기고 이긴다(사기 미적용). 즉 기지 방어가 현행보다 약해진다 (디버프라는 사용자 의도와 일치).
- 기지 ×1.3은 **구릉 방어(1.3)와 같은 강도**다 (검병 거울: 기지 56.6, 구릉 56.6). 산(1.6)은 기지보다 강하다. 기지가 지형 최강 요새가 아니게 된다.
- 양 채널에 모두 ×1.3을 주면 기지 방어가 한 채널일 때보다 6~7pp 강해져 "디버프" 의도와 어긋나므로 한 채널 안을 권장한다.
- γ=2에서 배율은 제곱으로 작용하므로 ×1.5 → ×1.3은 손실 비율상 "약 ×0.75" 수준의 하향이다.

### 2.3 편의 채널값과 가중치

편 s의 깃발 집합 M_s, 깃발 병력 m_f(milli), 사기 m와 헷갈리지 않도록 병력은 `troops_f`로 쓴다:

```
V_c(s)   = max(VMIN, floor( Σ troops_f * a_c(f) / Σ troops_f ))      VMIN = 100  [A-D3]
ωA(s)    = floor( Σ troops_f * POSTURE_W[posture_f][ATK] / Σ troops_f )
ω_ATK(s) = ωA(s),  ω_DEF(s) = 1000 - ωA(s)
```

`POSTURE_W` (확정): 공격 태세 `[ATK 600, DEF 400]`, 방어 태세 `[ATK 400, DEF 600]`.

### 2.4 채널별 비교 → 손실 몫 (γ=2 확정)

```
inv_c(s) = floor( 10^12 / V_c(s)^2 )
λ_c(s)   = floor( 10^6 * inv_c(s) / Σ_t inv_c(t) )
```

### 2.5 합성 → 손실 배분

```
raw(s)  = ω_ATK(s) * λ_ATK(s) + ω_DEF(s) * λ_DEF(s)             // <= 10^9
loss(s) = floor( T * raw(s) / Σ_t raw(t) )                      // T = 편 수 * L (불변)
잔여 = T - Σ loss(s) 를 편 key ASC 로 순환하며 1 milli씩 가산 (현행 방식)
loss(s) = min(loss(s), 편 병력)
```

정수 범위: `T * raw`는 T ≤ 약 9×10^6 milli(한 틱 손실 9,000명)까지 2^53 미만이라 사실상 안전 (현행 `T * iv`와 같은 수준). `inv_c`는 V ≥ 100이므로 ≤ 10^8, `10^6 * inv_c` ≤ 10^14.

### 2.6 합성 후보와 ω 선택

| 후보 | 장점 | 단점 |
|------|------|------|
| A. 고정 평균 (ω 500/500, 태세 무관) | 단순 | 태세가 지형표 행 선택 외 역할이 없음. 같은 병종 거울에서 태세 차이 소멸 |
| **B. 태세 가중합 (확정 형식)** | 태세가 "무엇으로 평가받는가"를 정함 | 가중치 상수 추가 |

ω·γ 민감도 (평지, 공격 대 방어, 공격측 손실%):

| 설정 | 기→창방 | 검→창방 | 검→검방(산) | 검→검방(구릉) |
|------|--------|--------|-------------|---------------|
| 현행 | 52.4 | 56.5 | 61.6 | 56.5 |
| ω500 γ1 | 53.7 | 51.5 | 55.8 | 53.3 |
| ω700 γ1 | 54.1 | 51.6 | 56.1 | 53.4 |
| **ω600 γ2 (확정)** | 57.0 | 53.1 | 61.5 | 56.6 |
| ω700 γ2 (rev.1 안) | 57.7 | 53.2 | 62.0 | 56.8 |
| ω800 γ2 | 58.5 | 53.4 | 62.6 | 57.0 |

- γ=2이면 방어 DEF 지형 배율을 현행 그대로(1.05/1.3/1.6) 두어도 거울 결과가 현행과 맞는다 (산 61.5 대 61.6, 구릉 56.6 대 56.5).
- **ω600의 부작용(주의)**: 기병은 ATK×DEF 곱이 0.826으로 낮아서, ω가 약 0.65 아래로 내려가면 공격 대 공격 조우전에서도 기병이 창병에게 진다 (손실: ω700 47.9% → **ω600 52.1%**). 사용자가 말한 "기병은 단기 돌파" 성격이 ω600에서는 첫 순간부터 나오지 않는다. 5.5절·열린 질문 M6에서 다룬다.

### 2.7 태세의 역할 (태세가 사라지지 않게)

1. **지형표 행 선택** (4.절)

### 2.8 이탈 0.7 (확정)

검병 거울, 이탈 대기 방어 깃발의 손실%: 현행(×0.5) 66.7 / 신규 ×0.5 80.0 / **신규 ×0.7 67.1**. γ=2에서 ×0.5는 효과상 ×0.25 수준이라 0.7로 맞춘다.

### 2.9 3편 이상, 테크

- 검(공)/창(방)/기(공) 각 300 → 편 손실%: 현행 38.2 / 29.4 / 32.4 → 신규 32.5 / 28.7 / 38.8 (기병이 가장 많이 맞음).
- 테크: 검병 거울에서 공격 테크 +14% 공격측 손실 현행 46.7 → 신규 46.7, 방어 테크 +14% 방어측 53.3 → 53.3. **같은 태세에서는 테크 효과가 현행과 일치**한다. 다만 공격 테크가 방어 태세 깃발에도 ω 40%만큼 작용한다.

## 3. 병종 능력치 표

### 3.1 권장: 현행 값 유지 [A-D7]

| 병종 | ATK | DEF | ATK×DEF (10^6) | 비고 |

### 3.3 상성 약화 문제 — 분석과 사기의 역할

- 현행 공vs방 평지 손실 범위는 37.2~59.9 (폭 22.7pp). 신규 채널 비교만 하면 44.1~57.0 (폭 **12.9pp**)로 좁다. 같은 종류끼리 비교하므로 창병의 높은 방어와 낮은 공격이 상쇄된다.
- 병종 표(U1·U2)로도 폭이 늘지 않는다 (U1은 오히려 더 좁다).
- **사기가 폭을 되살린다** (5.5절): 교전 10초 경과 시 폭 25.7pp(38.2~63.9), 20초 42.2pp(30.4~72.6), 30초 37.1pp. 사기가 시간에 따라 병종별로 다르게 줄기 때문이다. 사기를 넣으면 상성 폭은 "교전이 길수록" 현행보다 커진다.

### 3.4 기병 쏠림

쏠림의 구조적 이유는 전투 밖에 있다 (속도 1.45, 점령비 배율 0.85, 돌격 점령 1.4, 전환 1.15). 새 규칙에서:

- 기병이 방어 깃발을 칠 때 불리해진다: 평지 창 방어 52.4% → 57.0%, 검 방어 45.9% → 54.7% (채널 비교만으로).
- 사기를 더하면 교전이 길어질수록 더 불리하다 (5.5절 표: 20초에 창 방어 상대 72.6%).
- 반대로 **사기는 이동·점령(비전투) 중에는 회복**되므로, 기병이 교전을 피하고 점령만 하는 쏠림에는 영향이 없다. 점령비/속도 이점은 별도 조정이 필요하다 (열린 질문 Q8, 권장 기본값은 이번 범위 밖).

## 5. 사기 (Morale) — 세 번째 능력치

> 이 절의 **모든 수치는 에이전트 추측 [A-M]** 이다. 사용자 정의는 "매 전투마다 줄고, 줄면 전투력도 준다, 감소 속도는 기병 > 검병 > 창병" 뿐이다.

### 5.1 설계 요약

| 항목 | 초안 | 표시 |
|------|------|------|
| 단위 | **깃발 단위** `flag.morale` (0~1000‰, 시작 1000) | [A-M1] |
| 감소 시점 | **교전 중인 tick마다** (`inCombat`), 병종별 고정량 | [A-M2] |
| 전투력 반영 | 두 채널값에 `moraleMult(m)`을 곱함 | [A-M3] |
| 하한 | 사기 0이어도 전투력 60% | [A-M3] |
| 회복 | 비전투 tick마다 +3‰, 자기 기지 칸 위 +10‰ | [A-M5] |
| 병종 감소율 | 기병 10 / 검병 6 / 창병 3 (‰/tick) | [A-M4] |

### 5.2 함수

```
moraleMult(m) = 600 + floor( 400 * m / 1000 )      // m 1000 -> 1000‰, m 0 -> 600‰ (하한 X = 600)
```

사기 곱은 채널값 계산(2.2) 안에서 테크 다음, 이탈 앞에 들어간다. 두 채널에 같은 곱을 적용하므로 같은 병종끼리 사기가 같으면 효과가 상쇄된다. 병종이 다르면 사기 차이가 곧 전투력 차이가 된다.

### 5.3 병종별 감소율 표 (기병 > 검병 > 창병)

| 병종 | 감소 (‰/tick) | 감소 (‰/초) | 사기 0까지 | 10초 후 곱 | 20초 후 곱 | 30초 후 곱 | 60초 후 곱 |
|------|------|------|------|------|------|------|------|
| 창병 | 3 | 15 | 약 67초 | 940 | 880 | 820 | 640 |
| 검병 | 6 | 30 | 약 33초 | 880 | 760 | 640 | 600 |
| 기병 | 10 | 50 | 20초 | 800 | 600 | 600 | 600 |

(곱 값은 위 함수에 대입한 ‰.) tick = 200ms, 5Hz. "10초" = 50 tick.

테크: 새 스탯 `MORALE_DROP`(감소율 배율 ‰, 기본 1000), `MORALE_RECOVER`(회복 배율 ‰, 기본 1000)를 `TECH_STAT`에 추가하고 `drop' = max(1, floor(drop × MORALE_DROP / 1000))`. 사기 유지 노드(예: 감소율 -10%)는 군사 갈래나 병종 갈래에 둘 수 있다. 노드 배치·가격은 이 초안 범위 밖이며 [A-M7] (스탯 칸 추가 필요 — 백엔드가 `TECH_STAT_BASE` 길이와 `match_config.constants`를 같이 갱신).

### 5.4 갱신 규칙 (결정론)

4b 마지막(inCombat 갱신 이후)에 깃발 `flagId ASC`로:

```
if (f.inCombat)                 m = max(0, m - dropPerTick(unit, tech))
else if (onOwnBase(f))          m = min(1000, m + RECOVER_BASE(10) * techRecover / 1000)
else                            m = min(1000, m + RECOVER(3) * techRecover / 1000)
```

다음 tick의 4a가 갱신된 m을 읽는다 (4a는 읽기 전용 유지). 정수 ‰ 하나만 있으니 순서 의존성이 없다.

- **회복 후보 R1 (권장)**: 비전투 tick마다 +3‰ (0→1000 약 67초), 자기 기지 칸 위에서는 +10‰ (약 20초). 귀환·이동·점령 중에도 회복되므로 "전투를 쉬면 돌아온다"는 직관과 맞고, 기지에 돌려보내 재충전하는 교대 전략이 생긴다.
- **회복 후보 R2**: 귀환 완료(기지 도착) 시 1000으로 즉시 복구, 그 외엔 회복 없음. 규칙이 단순하고 UI가 쉽지만, 기병이 점령만 하며 사기를 유지하는 것과 무관하게 항상 귀환이 최적이 되어 이동 흐름이 끊긴다.
- **교전 1회당 감소(대안)**: `combat_started` 합류마다 일정량 감소. 한 번 짧게 맞붙었다 빠지는 것과 오래 싸우는 것이 같아져 "오래 싸울수록 약해짐"이 사라지고 합류 이벤트 남용(어뷰징) 여지가 있다 → 교전 tick당 감소를 권장한다.

| 상황 | 초안 | 표시 |
|------|------|------|
| 이탈 대기(disengage, 3초) | 아직 inCombat이므로 사기 계속 감소. 값은 ×0.7 | [A-M8] |
| 이탈 완료(breakaway)·교전 종료 | 비전투 → 회복 시작 | [A-M8] |

| 재출전(새 병력 편성) | 깃발의 현재 사기를 이어받음 (리셋 없음) | [A-M8] |

### 5.7 판 길이·페이싱 영향

- `T = 편 수 × L`을 바꾸지 않으므로 교전 한 tick당 총 사망 병력은 같다. 사기는 이 총량을 **나누는 비율**만 바꾼다. 위 동적 시뮬레이션에서 교전 길이는 ±15% 안이고 사기를 넣으면 약 10~15% 짧아진다.
- 간접 영향: 사기가 낮은 깃발은 교전을 피하고 회복하러 돌아가야 하므로 공세의 연속성이 줄어든다. 이는 판 길이를 늘릴 수도 줄일 수도 있어 **정량 예측 불가** — 자가대전 측정 필요 (구현 단계 6).
- 정수/결정론: 사기는 깃발당 정수 ‰ 하나, 4b에서 flagId ASC로 갱신, 4a는 읽기만 하므로 기존 결정론 구조에 영향이 없다.

### 7.1 봇 (`server/src/game/bot.ts`)

`flagValue`를 **스칼라 전투값**으로 쓰는 곳이 영향을 받는다.

스칼라 근사(`v = (ω_ATK·a_ATK + ω_DEF·a_DEF)/1000`, ω600)와 참값의 차이는 최대 약 4.5pp이고 **S11은 승패 방향이 뒤집힌다** (참값 54.7% vs 스칼라 50.3%). 그래서:

- **[A-D11]** `combat.ts`에 순수 함수 `sideLossShares(state, sides)`를 공개하고 4a가 그것을 호출. 봇은 이 함수로 예상 손실 비율을 정확히 계산. `flagValue`는 호환용 스칼라로 남김.
- 봇 상수 재측정: `BOT_ENGAGE_BREAK_RATIO_PERMILLE`, `BOT_INTERCEPT_RATIO_PERMILLE`, `retreatRatioPermille`.
- **사기 대응 신규**: 봇은 사기가 낮은(예: < 400) 깃발을 교전에서 빼 기지로 돌려 회복시키고, 사기 격차가 큰 적을 우선 공격하는 규칙이 필요하다 (현재 봇은 사기 개념이 없음). 이 규칙 없이 사기만 도입하면 봇이 사기 0 상태로 계속 싸워 약해진다.

### 7.2 프로토콜 (사기 보강)

- **깃발 상태에 `morale` 필드 (0~1000, 정수 ‰) 추가** [A-M9]: `snapshot_full`의 깃발 객체, 개인 스냅숏, 델타의 깃발 변경분. 새 필드라 구 클라이언트는 무시한다.
- **동기화 빈도**: 사기는 교전 중·회복 중 매 tick 바뀌므로 매 tick 델타를 보내면 대역폭이 늘어난다. 초안: 델타 `moraleChanged: [[flagId, morale], ...]`을 **5 tick(1초)마다 한 번**, 변한 깃발만. 클라이언트는 `inCombat` 여부와 병종 감소율 상수(`match_config.constants`)로 사이 값을 선형 보간해 표시. 서버 권위 값은 1초마다 정정.
- `combat_started.sides[].power`: rev.1과 같이 의미를 "ω 평균 스칼라(사기 반영, 표시·호환용)"로 바꾸고 선택 필드 `atk`, `def`, `lossPermille`(예상 손실 비율, 편 합 1000), **`morale`(편 평균)** 추가 [A-D12].
- `match_config.constants`에 새 상수 노출: 채널 표, `TERRAIN_BUFF`, `BASE_BUFF`, `POSTURE_W`, γ, VMIN, 이탈 700, 사기 상수(`MORALE_FLOOR` 600, `MORALE_DROP_PER_TICK[3]`, `MORALE_RECOVER`, `MORALE_RECOVER_BASE`). 폐기: `COMBAT_TERRAIN_DEF_POSTURE_PERMILLE`, `COMBAT_BASE_ATK/DEF_PERMILLE` (새 표로 대체).
- 02 프로토콜 문서에는 새 절이 필요하다 (이 초안은 02를 건드리지 않음). 재접속 스냅숏에 `morale`이 있어야 하며, 관전 모드도 동일.

### 7.3 클라이언트 표시

- 깃발 아이콘/정보창: 병력 수 옆에 **사기 막대**(색: 만땅 → 바닥으로 갈수록 경고색, 색 외에 수치/모양도 병행), 툴팁에 `ATK 1,121 / DEF 910 (사기·지형 반영)`.
- 교전 막대: `lossPermille`로 예상 손실 비율. 기존 `power` 기반 교환비 대체.
- 타일 툴팁: 지형별 "공격 태세 ATK +10% / 방어 태세 DEF +30%".
- 교전 예상 UI(제안): 내 깃발을 적 깃발에 가져다 대면 "예상 교환비 / 현재 사기 기준 승패 / 20초 뒤 예상"을 표시. 채널 계산 함수를 `shared/`로 올려 서버·클라이언트가 같은 코드를 쓰는 안 (열린 질문 Q7).

## 8. 위험과 대안

### 8.1 위험

1. **상성 폭 약화는 사기에 의존**: 채널 비교만으로는 폭이 12.9pp. 사기가 오작동·미튜닝이면 상성 약화 문제가 그대로 남는다.
2. **기병 단기 돌파가 안 나온다**: ω600이면 조우전 첫 순간부터 기병이 창병에게 약간 불리 (5.5절). 의도와 다르면 ω 또는 "기세" 보너스 조정이 필요.
3. **사기 어뷰징**: 사기가 낮은 깃발을 일부러 기지에 두면 회복이 빠르다(+10‰/tick). 반대로 교전 합류·이탈 반복으로 상대 사기를 깎는 소모전이 생길 수 있다. 감소를 교전 tick 단위로 한 것이 이를 완화.
4. **플레이어 설명 가능성**: 채널 2개 + ω + 지형 + 사기가 겹친다. UI(7.3) 부실 시 결과 예측 불가로 느껴짐. 사기 막대와 예상 UI 우선 구현 필요.
5. **봇**: 사기 개념이 없으면 소모전에서 불리 → 봇 로직 신규 (7.1).
6. **프로토콜**: 사기 동기화 대역폭, `power` 의미 변경.
7. **튜닝 파라미터 증가**: ω, γ, VMIN, 지형표, 사기 5종 + 테크. 단계별 측정 필수.
8. **정수 범위**: 2.5 분석으로 안전, 테스트 필요.

## 9. 구현 단계 제안

1. **shared**: 채널 상수/표, `techChannelPm`, 사기 상수와 `moraleMult`. 필요하면 순수 계산 함수를 `shared/src/combatMath.ts`로.
2. **server**: `GameState`에 `flag.morale`, `combat.ts` 4a를 `sideLossShares`로 교체, 4b 끝에 사기 갱신. 환경 플래그(`COMBAT_MODEL=2`)로 현행과 병존. 단위 테스트.
3. **bot**: 후퇴·요격 정확 함수, 사기 기반 교대 규칙, 상수 재측정.
4. **protocol**: `morale` 필드, `moraleChanged` 델타, `combat_started` 필드, `match_config.constants`, 문서 새 절.
5. **client**: 사기 막대, 정보창, 교전 막대, 예상 UI, 타일 툴팁, 테크 문구.
6. **자가대전 비교**: 시드 1000~1019, M 10인 NORMAL 봇 (§29.3 조건). 교전 길이 분포, 병종 비율, 후퇴 빈도, 승패 시간을 현행 대비 측정 (`ai-match-monitor` 기록). 사기 감소율 표를 이 측정으로 조정.
7. 사용자 승인 후 현행 모델 삭제.

## 부록 B. 사기를 비교 채널로 승격하는 경우 (대안, 사용자 결정 전 참고)

본문은 사기를 **곱 계수**로 둔다. 비교 채널로 승격하면: 병종마다 사기 값 `m`을 `V_MOR(s)`로 편 평균, `λ_MOR`을 같은 γ 식으로 구하고 ω가 3성분(예: 공격 태세 `[ATK 500, DEF 300, MOR 200]`)이 된다. 장점은 "채널 확장" 구조에 충실하다는 것, 단점은 (1) 사기 곱과 달리 병종 상성 방향이 사기 차이에 직접 연동되어 계산 의미가 불투명하고, (2) 지형표가 3열로 늘고 테크 스탯이 늘며, (3) 사기가 낮은 쪽이 전투력 감소가 아니라 "비교 채널에서 지는 쪽"이 되어 사용자 정의("사기가 줄면 전투력도 준다")와 거리가 있다. 그래서 본문은 곱 계수 안(M10)을 권장한다.
