## 1. 트리 구조

### 1.1 규칙 `[A-66]`

1. **노드마다 부모는 최대 하나.** T1 노드는 부모가 없다(처음부터 살 수 있다). T2 노드의 부모는 같은 갈래의 T1, T3 노드의 부모는 같은 갈래의 T2 하나다.
2. 부모를 샀으면 자식을 살 수 있다. **형제 노드를 다 살 필요는 없다** — 한 갈래 안에서도 길을 고른다.
3. 갈래를 건너뛰는 선행 관계는 없다. 7개 갈래의 T1은 시작부터 모두 열려 있다.
4. 구매는 즉시 발효되고 되돌릴 수 없다(현행과 같다).

**왜 부모 하나인가.** 서버 검증이 `owned[parent[id]]` 비트 하나로 끝나서 결정론 보증이 쉽고, 화면에서도 선이 노드마다 한 개라 겹치지 않는다. 부모가 여럿이면 선이 엇갈리고 "왜 못 사지?"를 설명하기 어려워진다. 다른 방식은 7장 A-66에 선택지로 남겼다.

**병종 업그레이드가 상성을 만들지 않는 이유.** 병종 노드는 그 병종의 **원래 역할 스탯만** 키운다 — 창병은 버티기(DEF·유지비), 기병은 빠르기(속도·편성·유지비), 검병은 기준형(ATK·DEF·점령비용 고루). "기병을 상대할 때 +X%" 같은 상대 조건 효과는 하나도 없다. 상대가 무엇을 보냈는지가 아니라 **내가 어떤 병종으로 싸우기로 했는지**에 투자하는 구조라 GDD 4.11(a) "상성이 아니라 역할 분화" 원칙이 그대로 지켜진다.

## 2. 노드 표 `[A-72]`

### 2.1 가격식 `[A-69]` `[A-70]`

```
cost(node, n) = floor( TECH_NODE_BASE_COST[tier(node)] × (1000 + TECH_PROGRESSIVE_COEF_PERMILLE × n) / 1000 )
TECH_NODE_BASE_COST = [160, 360, 700]        // T1, T2, T3
TECH_PROGRESSIVE_COEF_PERMILLE = 60           // 구매 1회마다 +6%
n = 그 플레이어가 지금까지 산 노드 수 (갈래 무관)  — 현행 purchasedCount와 같은 정의
```

아래 표의 "비용"은 기본값(n = 0)이다. 실제 값은 산 노드가 많을수록 올라간다(n = 8이면 ×1.48, n = 14면 ×1.84).

### 2.2 효과를 계산식에 넣는 방법 `[A-71]`

같은 스탯에 걸리는 노드가 여러 개면 **permille 증분을 더한다**(곱하지 않는다).

```
statPm(p, S) = 1000 + Σ { node.deltaPm : node ∈ owned(p), node.stat == S }      // 정수 덧셈만
```

- 예: 깃발 이동속도 = MOB-1(+150) + MOB-2A(+150) = 1300. 기병이면 CAV-1(+100)까지 더해 1400. 실제 속도 = `UNIT_SPEED × statPm / 1000`.
- 감소 효과는 음수 증분이다(예: MIL-1 적 땅 점령비용 −40 → 960).
- 고정값 덮어쓰기(물 이동배율, 상륙 손실, 유지비 가중치)는 "노드 보유 시 이 값"으로 정의한다 — 같은 스탯을 덮는 노드가 하나뿐이라 순서 문제가 없다.
- 더하기만 쓰므로 구매 순서와 상관없이 같은 값이 나온다. tick마다 다시 더하지 않고 **구매 시점에 플레이어별 캐시**(`p.statPm[S]`)를 갱신한다.

### 3.3 "총 투자는 현행과 비슷한가" — 판정

- **버는 골드는 그대로다.** `GOLD_RATE_PERMILLE`, `START_GOLD`, 유지비 산식은 손대지 않는다.
- **테크에 쓰이는 골드는 늘어난다(선두 49% → 86%).** 현행은 5번째 노드가 5,200이라 선두가 마지막 8분간 4,700골드를 쓰지 못하고 들고 있다. 노드를 잘게 쪼개면 이 골드가 테크로 간다. 이것이 "같은 골드로 테크 효과가 더 커지는" 유일한 경로다.
- **골드당 효과는 T1 기준으로 현행과 같은 수준으로 맞췄다.**

| 비교 | 현행 T1 | 제안 T1 | 골드 1당 효과 (제안/현행) |
|---|---|---|---|
| 기동 속도 | 450골드 → +45% | 160 → +15% | 0.094 / 0.100 = **0.94** |
| 경제 골드 | 450 → +25% | 160 → +8% | 0.050 / 0.056 = **0.90** |
| 영토 중립 | 450 → −12% | 160 → −6% | 0.038 / 0.027 = 1.41 (현행 영토 T1은 효과 2개라 단순 비교 불가 — 병력 상한 +10% 포함 시 약 1.0) |
| 군사 | 450 → 적 −7%, 내 +7%, 전투 +2.5% | 160 → 적 −4% | 약 0.95 |

- 결론: 노드당 가치는 현행의 약 0.9~1.0배, 쓰이는 골드는 1.75배 → **선두 기준 테크 총효과는 현행의 약 1.5배 쪽으로 움직인다.** 다만 큰 스탯(속도·골드·슬롯)의 천장을 낮췄고(2.4), 효과가 32개 스탯 칸에 흩어지므로 한 방향으로 몰아서 얻는 이득은 현행보다 작다. 이 쏠림이 걱정되면 `TECH_PROGRESSIVE_COEF_PERMILLE`를 60 → 80으로 올리면 선두 13 / 중위 8 / 조기 탈락 4(쓰이는 골드 약 80%)가 된다 — 7장 A-69 대안.

```
// 깃발 전투 (4.15 d) — MIL_COMBAT_PERMILLE_BY_TIER[militaryTier] 를 아래로 교체
combatAtkPm(p, u) = 1000 + Σ deltaPm(stat = COMBAT_ATK_ALL) + Σ deltaPm(stat = COMBAT_ATK[u])
combatDefPm(p, u) = 1000 + Σ deltaPm(stat = COMBAT_DEF_ALL) + Σ deltaPm(stat = COMBAT_DEF[u])
v_atk = UNIT_ATK_PERMILLE[u] × combatAtkPm / 1000 × (지형 등 기존 항)
// 최대 v = 1300 × 1600/1000 × 1140/1000 = 2371 — int32 여유 충분 (현행 상한 2236)

// 이동 (4.4) — MOB_SPEED_PERMILLE_BY_TIER 교체
speedPm(p, u) = 1000 + Σ deltaPm(FLAG_SPEED_ALL) + Σ deltaPm(FLAG_SPEED[u])

// 점령비용 (4.6 b) — 기존 atkCostMult / defCostMult / neutralCostMult 자리에 statPm 을 그대로 넣는다
// 유지비 (4.4 a) — GARRISON_UPKEEP_PERMILLE, UNIT_GARRISON_PERMILLE[u] 를 플레이어별 값으로 읽는다
// 보급선 (4.6 c) — SUPPLY_COEF_PERMILLE 을 플레이어별 값으로 읽는다
```

### 5.1 공통 요소

**열고 닫기** `[A-84]`: 하단 바의 "테크" 버튼 또는 `T` 키. 버튼에 **지금 살 수 있는 노드 수** 배지(예: `테크 2`). 열려 있어도 게임은 계속 돌아가므로 맵을 다 가리지 않는다(반투명 배경, 오른쪽 또는 아래쪽 맵이 보임).

**노드 상태 5가지** `[A-79]` — 색만으로 구분하지 않고 테두리 모양·기호를 함께 바꾼다(색각 이상 대응).

| 상태 | 조건 | 모양 |
|---|---|---|
| 잠김 | 부모 미보유 | 회색 아이콘 40% 투명, 점선 테두리, 오른쪽 위 작은 자물쇠. 가격 숨김 |
| 골드 부족 | 부모 보유, 골드 < 가격 | 갈래 색 얇은 실선 테두리, 아이콘 정상, 가격 회색. **테두리를 따라 도는 진행 링** = 현재 골드 / 가격 |
| 구매 가능 | 부모 보유, 골드 ≥ 가격 | 갈래 색 굵은 실선 테두리, 가격 진하게. 한 번 짧게 깜빡인 뒤 정지(계속 깜빡이지 않는다) |
| 구매 요청 중 | 클릭 후 서버 확인 전 | 테두리 점멸 없이 아이콘 위 작은 시계 |
| 보유 | 서버가 `tech_purchased` 확인 | 갈래 색으로 칠한 원, 아이콘은 흰색으로 반전, 아래 작은 체크 |

**연결선**: 부모 → 자식, 노드마다 선 하나(부모가 하나뿐이라 겹치지 않는다).

| 부모 상태 | 선 |
|---|---|
| 부모 보유 | 갈래 색 실선 2px |
| 부모 미보유 | 회색 점선 1px |
| 마우스를 올린 노드의 선행 경로 | 루트까지 경로를 굵게 강조 |

**가격이 바뀌는 점 안내**: 노드를 하나 살 때마다 남은 노드 가격이 전부 6% 오른다. 상세 패널에 "다음 구매부터 모든 노드 +6%"를 한 줄로 적고, 구매 직후 가격 숫자를 짧게 갱신 애니메이션한다.

### 5.4 안 C — 방사형

## 6. 봇 영향 (GDD 8.5 테크 우선순위) `[A-82]`

### 6.1 규칙

- 현행 규칙 유지: 결정 tick마다 목록에서 **아직 안 산 첫 노드**를 살 수 있으면 즉시 산다. 못 사면 기다린다(건너뛰지 않는다).
- 목록은 부모가 항상 자식보다 앞에 오게 짠다. 서버 시작 시 assert.
- 목록 길이 16(선두 봇이 14~15개를 사므로 끝까지 가도 남는다).
- **병종 치환**: EASY 봇은 검병만 쓴다(`fixedUnit = SWORD`). 목록의 병종 노드를 자기 병종 쪽으로 바꾼다 — `CAV-1 → SWO-1, CAV-2A → SWO-2B, CAV-2B → SWO-2A, CAV-3 → SWO-3`(부모 관계가 같은 자리끼리). SPE 노드는 그대로(방어 깃발은 창병을 쓸 수 있으므로).
- 봇 판단식 중 `militaryTier`, `MIL_COMBAT_PERMILLE_BY_TIER`를 읽는 곳(요격 비율·회피 판단의 v 비교)은 4.3의 `combatAtkPm / combatDefPm`로 바꾼다.

### 6.2 성향별 목록 (`TECH_PRIORITY[bot.botIndex % 4]`)

실측상 봇 공격 깃발의 97%가 기병이고 방어 비중이 47%라서, 4종 모두 기병 노드와 창병 또는 유지비 노드를 일찍 넣었다.

```
          ECO-3B, SPE-1, MIL-1, MOB-2A, CAV-3, TER-2B, SPE-2A, MOB-3A
2 수비형: SPE-1, MIL-1, ECO-1, SPE-2A, MIL-2B, CAV-1, ECO-2B, SPE-3,
          MIL-3B, MOB-1, TER-1, TER-2B, MOB-2A, MOB-3A, SPE-2B, TER-3B
```
