## 5. 작업 방식 — 토큰 절약 (중요)

이 프로젝트에서 **한 번 실패했고, 고쳐서 성공한 방식**이다. 반드시 따를 것.

- ❌ **실패**: "GDD v3.1로 개정하라"고 통째로 넘김 → 에이전트가 2,400줄 전체를 읽다가 예산 소진, **산출물 0으로 중단**됨
- ✅ **성공**: 읽을 절을 **줄번호로 못 박고**, 그 외에는 `Grep`으로 좁히게 하고, **"총 읽기 500줄 이내"** 를 프롬프트에 명시 → 136K 토큰으로 완료
- ✅ 문면 정리·enum 추가처럼 **기계적인 편집은 오케스트레이터가 직접** 한다. 에이전트를 쓰지 않는다
- ✅ 재검산이 무거운 절(5장 등)은 **별도 호출로 분리**한다
- 줄번호는 편집하면 밀리므로, 넘기기 직전에 `Grep`으로 다시 뽑을 것

## 6. 절대 어기면 안 되는 것

- **승인 게이트**: 사용자 승인 없이 Phase 3 착수 금지 (`CLAUDE.md`, `civwar-orchestrator` 스킬)
- **임의 결정 금지**: 설계 결정은 사용자에게 묻는다. 에이전트가 빈칸을 메우며 발명한 것은 `[A]`로 분류해 승인받는다
- **결정론**: `Math.sqrt`·정수·`floor/ceil`만. 분수 지수 금지. 배율은 permille 정수, 누적 자원은 1/1000 고정소수점
- **Phase A(읽기 전용) / Phase B(쓰기) 분리**, 순회는 `flag.id ASC` / `tileId ASC` / `playerId ASC`
- **타일의 가변 상태는 `owner` 하나** (유일한 예외: 기지 체력). 진척도는 타일이 아니라 **깃발**에 산다
- **토폴로지 추상화**: `neighbors` / `distance` / `tileCount`만 사용. `row*width+col`, manhattan, `id ± 1 / id ± width`를 게임 로직에 박지 말 것
- **Notion 동기화는 오케스트레이터가 직접** 수행한다. 서브 에이전트에 위임하지 않는다. `update_content`로 해당 섹션만, `replace_content` 금지. 페이지 `civwar.io`, `page_id: 3b2286f3-bd70-8002-84bf-c9ddce1d9a57`
- 사용자 대상 응답은 **한국어**

## 9. 알려진 설계 구멍 (알고 남긴 것)

- **소규모 농성**: 좁은 영토 4슬롯 농성이 골드 유지비 27% 둔화만 물고 성립한다. 사용자가 **알고 수용**했고 누진을 기각했다. 관측은 GDD `[B] B-10`
- **웅크리기 차단**: 골드 단독으로는 불성립. 기하학(슬롯 7 < 필요 9.2) + 골드 템포 + 승리조건의 3중 합으로 대체 (GDD 4.4c)
- **점유율 분모 오염**: 산 8%가 중립으로 남으면 임계 45%가 실질 47.4%가 된다 (`[B] B-9`). **물로 갈린 섬은 아직 이 항목에 포함돼 있지 않다**
