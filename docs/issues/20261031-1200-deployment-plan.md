## 맥락
2026-10-31 기준 레포에는 배포 설정(Dockerfile, docker-compose, fly.toml, vercel.json, render.yaml, GitHub Actions)과 배포 문서가 전혀 없다. 지금은 로컬 개발·봇 대전·QA 스크립트 단계다.

현재 코드에서 확인한 사실:
- `client/vite.config.ts`: 개발용 프록시만 있다. 서버 주소는 `CIVWAR_SERVER` 환경변수(기본 `ws://localhost:8080`). 클라이언트는 `?ws=` 쿼리로도 서버 주소를 받는다.
- 서버는 Node.js + TypeScript + `ws` 권위 서버이고, 틱 루프로 상태를 메모리에 들고 있는 상주 프로세스다. DB는 없다.
- 한 판은 25~32분이고 한 방이 한 프로세스에 묶인다.

초기 방향안 (제안일 뿐 확정 아님):
- 클라이언트: Vite 정적 빌드 → Vercel / Cloudflare Pages / Netlify 같은 정적 호스팅.
- 서버: 상태를 메모리에 들고 있으므로 서버리스는 부적합. Fly.io / Railway / Render 같은 컨테이너 호스팅 또는 VPS 한 대.
- 스케일: 처음에는 단일 인스턴스. 방 단위로 프로세스를 나누는 방식은 접속자가 늘면 검토.

결정 필요: 예산, 예상 동시 접속자 수, 선호 플랫폼, 도메인 보유 여부.
